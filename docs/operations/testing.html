Profile-Level Contract Tests

Unit tests are not enough for cross-package lakehouse wiring.

Phlo supports profile-level contract tests:

  • bundled stack contracts real services, local workspace source, versioned and publish flows
  • non-versioned profile contracts local DuckDB + dbt verification without the bundled service stack

Use these when you need to verify:

  • canonical runtime routing
  • ref-aware writes and promotion
  • generated dbt profile behavior
  • publish-target wiring
  • full cross-package integration

Integration Testing

Integration tests require the full Docker stack and test end-to-end pipelines.

Core Service Auto-Configure Validation

Use this checklist after a fresh install or when core service definitions change.

Edge cases to watch:

  • SUPERSET_ADMIN_PASSWORD is injected into Dagster even if Superset is not installed; set it only when enabling Superset.
  • PHLO_VERSION is optional (blank uses latest) for the Dagster image build.
  • PHLO_HOST_PLATFORM should be set for macOS hosts that need explicit Linux/amd64 builds.

Best Practices

1. Test Schema First

Always test your Pandera schema before testing the full pipeline:

Why: Schema errors are the most common issue. Catching them early saves time.

2. Use Descriptive Test Names

Why: Clear names make failures easier to diagnose.

3. One Assertion Concept Per Test

Why: Specific failures are easier to debug.

4. Use Fixtures for Test Data

Why: Reduces duplication, makes tests more maintainable.

5. Mark Integration Tests

Why: Enables running fast tests separately from slow tests.

6. Test Error Cases

Why: Error handling is as important as happy paths.

Troubleshooting

Test Discovery Issues

Problem: pytest doesn't find your tests

Solution:

  • Ensure test files start with test_
  • Ensure test functions start with test_
  • Ensure test classes start with Test
  • Check pytest.ini configuration

Schema Validation Failures

Problem: Valid data fails schema validation

Solution:

  • Check field types match (str vs datetime)
  • Check nullable settings
  • Check constraint values (ge, le, etc.)
  • Use coerce=True in schema Config

Test Coverage

Measuring Coverage

Coverage Goals

  • Schema validation: 100% (easy to test)
  • Decorator configuration: 100% (easy to test)
  • Business logic: 90%+ (important to test)
  • Integration paths: 70%+ (harder to test)

Next Steps

  1. Start with schema tests: Use the example in this guide or the scaffolded test file
  2. Add business logic tests: Test any custom transformations
  3. Add integration tests: Test full pipelines when ready
  4. Set up CI/CD: Run tests on every commit
  5. Track coverage: Aim for 80%+ overall coverage
